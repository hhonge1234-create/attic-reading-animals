# 발표 슬라이드 계획: 다락방 서재에 놀러 온 동물들

## 목표
- 문헌정보학과 바이브 코딩 공모전 발표. 시간 약 7~10분.
- 전달할 것: 만든 이유 → 서비스 구조 → 만든 과정(바이브 코딩) → 서비스 운영 방법 → 가치.
- 형식: 직접 만든 HTML 슬라이드 덱(1920×1080 캔버스를 화면에 맞춰 확대·축소), 키보드와 클릭으로 넘김, GitHub Pages 배포.

## 시각 자료 원칙
- **anime.js**: 슬라이드에 들어올 때 요소 등장, 숫자 올라가기, 막대 채우기, 선 그리기, 동물 사진 흔들림.
- **manim**: 개념 애니메이션 영상 2개. (1) 4개 축이 갈라져 16마리가 되는 나무 (2) 입력 → 점수 → 유형 코드로 이어지는 계산 흐름.
- **matplotlib**: 데이터 그래프. 사이트와 같은 수채 색감(크림, 나무색, 빛바랜 빨강)으로 맞춘 SVG.
- **데이터는 실제 값만** 씁니다. 지어낸 통계는 쓰지 않습니다.
  - 사이트 코드의 상수: 분야별 가중치, 질문 가중치, 내장 도서 72권의 유형 분포, 백분율 곡선(tanh), 출간연도 점수표
  - 알고리즘 시뮬레이션: 가상의 응답 10,000개를 무작위로 넣어 본 유형 분포. 화면에 "시뮬레이션"이라고 표시합니다.
  - 제작 기록: 사이트 배포 버전 10개의 실제 시각
  - 외부 데이터 시험 결과: Google Books 할당량 0(429 오류), Open Library 한국 책 검색 결과 수

## 슬라이드 구성 (20장)

| # | 제목 | 핵심 메시지 | 시각 자료 |
|---|---|---|---|
| 1 | 표지 | 다락방 서재에 놀러 온 동물들 | 수채 다락방 배경, 빨랫줄 동물 사진이 떨어져 걸리며 흔들림(anime), 먼지 입자 |
| 2 | 문제 | 책은 많은데 다음 책 고르기가 어렵다 | 카드 3장 순서대로 등장 |
| 3 | 아이디어 | 독서 성향을 MBTI처럼 4축 16유형으로 | manim: 4번 갈라지는 나무 → 16마리 |
| 4 | 4개의 축 | 무엇으로 각 축을 정하나 | 축 4개 슬라이더가 움직이는 애니메이션 |
| 5 | 16마리 도감 | 16마리를 한 장에, 6×3 격자로 그림을 최대한 크게 | 그림 순차 등장(stagger) |
| 6 | Google Flow 프롬프트 | 고래 프롬프트 원문 → 후보 2장 → 고른 그림 → 도감 카드 | 프롬프트 타자 효과, 후보 선택, 카드 떨어짐(anime) |
| 6 | 문헌정보학과의 연결 | 분류, 참고면담, 독자 상담, 정보 접근 | 아이콘 카드 4장 |
| 7 | 이용 흐름 | 입력 3단계 → 사서 분석 → 결과 6가지 | 연결선이 그려지는 흐름도(anime) |
| 8 | 점수 계산 ① | 분야 선택이 축에 주는 가중치 | matplotlib 히트맵(실제 가중치) |
| 9 | 점수 계산 ② | 점수가 퍼센트로, 연도가 고전/신간으로 | matplotlib 곡선 2개 + manim 계산 흐름 영상 |
| 10 | 한 사람의 분석 예시 | 예시 입력이 고래(SDEC)가 되기까지 | 막대가 실제 퍼센트까지 차오름(anime) |
| 11 | 알고리즘 시뮬레이션 | 무작위 응답 1만 개의 유형 분포 | matplotlib 막대 그래프 |
| 12 | 서비스 화면 | 실제 화면 4컷 | 캡처가 차례로 넘어감 |
| 13 | 만든 과정 | 한 시간 남짓, 10번의 배포 | matplotlib 타임라인(실제 시각) |
| 14 | 외부 데이터의 벽 | 도서 API를 쓸 수 없었던 이유와 해결 | 시험 결과 표 + 전환 다이어그램 |
| 15 | 시행착오 4가지 | 문제 → 해결 | 카드가 뒤집히며 해결이 나타남 |
| 16 | 기술 구조 | 서버 없는 한 장짜리 웹 | 구조도, 선 그리기 애니메이션 |
| 17 | 서비스 운영 방안 | 어디서, 어떻게 쓰이게 할까 | 단계별 로드맵 |
| 18 | 가치 | 이용자, 도서관, 전공 | 3단 카드 + 행운의 독서템 조합 수 카운터 |
| 19 | 마무리 | 당신의 다락방에는 누가 놀러 왔나요? | QR 코드, 링크 |

## 검증 루프
1. 슬라이드마다 1920×1080으로 캡처해 눈으로 확인합니다.
2. 자동 점검: 캔버스 밖으로 넘친 요소, 글자 잘림, 불러오지 못한 이미지·영상, 콘솔 오류를 찾습니다.
3. 문제가 있으면 고치고 1~2를 다시 합니다. 문제가 없을 때까지 반복합니다.
4. 배포 뒤에도 Pages 주소에서 한 번 더 확인합니다.

## 배포
- `gh repo create`로 공개 저장소를 만들고 push한 뒤 `gh api`로 Pages를 켭니다.
- `/` = 서비스(체험판), `/slides/` = 발표 슬라이드.


## 개정 계획 (2026-11-08, 서비스 업데이트 반영)

서비스에 생긴 변화: 다락방 이웃들의 책장(구글 시트 DB), 무료 체험 페이지(GitHub Pages)와 정밀 분석 페이지(본인 Claude 계정)로 나뉜 구조, 도서명·저자 칸 분리, 쉬운 10개 분야.

| 슬라이드 | 바꿀 내용 | 시각 자료 |
|---|---|---|
| 이용 흐름 | 결과에 ‘이웃들의 책장’ 추가 (결과 7가지) | 흐름도 선 그리기 |
| **새: 다락방 이웃들의 책장** | 내 책 → 구글 시트에 익명 저장 → 동물별 책장. 개인정보 저장 안 함 | 3단계 흐름 + **발표 순간의 실제 책장을 시트에서 불러와 책등으로 표시**(불러오지 못하면 캡처로 대체) |
| 서비스 화면 | 최신 화면으로 다시 캡처: 첫 화면, 입력(도서명·저자, 책장 동의), 결과와 정밀 분석 안내, 이웃 책장 | 화면 전환 애니메이션 |
| 만든 과정 | 처음 76분 이후에 더한 것(발표 슬라이드, 이웃 책장, 본인 Claude 연결) 한 줄 추가 | 기존 타임라인 유지 |
| 기술 구조 | 두 페이지 + 구글 시트 + Claude 사서 + 국립중앙도서관. ‘데이터베이스 없음’ 문구 삭제 | 구조도 다시 그리기, 선 애니메이션 |
| **새: 두 개의 문** | 무료 체험(모두의 책장, 내장 71권)과 정밀 분석(본인 Claude)으로 나눈 이유, 한 페이지 통합 방안(API 키) | 두 카드 비교 |
| 서비스 운영 방안 / 가치 / 한계 | 책장 반영, 한계 문구 갱신 | 기존 유지 |
| 마무리 | 체험 주소 QR 유지, 정밀 분석 링크 추가 | |

데이터 원칙은 그대로입니다. 책장 숫자는 발표하는 순간 시트에서 읽은 실제 값만 보여 줍니다.
